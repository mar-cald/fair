La skill fair-check

Controllare la cartella del progetto con un assistente AI e prepararla per il deposito

Parole chiave: skill Agent Skills Claude ChatGPT Codex OpenAI Anthropic intelligenza artificiale AI assistente controllo cartella verifica progetto FAIR deposito pronto Zenodo PsychArchives; data dictionary automatico README licenza Psych-DS; codice riproducibile numeri manoscritto preprint; punteggi totali item invertiti; Qualtrics PsychoPy jsPsych Gorilla OpenSesame E-Prime.

fair-check è una skill: una cartella di istruzioni e di script in Python che un assistente AI (Claude, ChatGPT/Codex e altri) segue quando gli chiedete di controllare la cartella di un progetto di ricerca. Applica le regole di questa dispensa e vi restituisce due cose:

  • un rapporto: che cosa impedirebbe a un estraneo di trovare, aprire, capire e riusare i vostri dati e il vostro codice, file per file, e quali numeri del manoscritto non tornano con i dati o con l’output degli script;
  • se lo chiedete, una versione della cartella pronta da depositare su Zenodo o su un altro repository, con README, data dictionary, licenze e lo zip da caricare.

La vostra cartella non viene modificata.

Da scaricare

fair-check.skill: un archivio zip che contiene la cartella fair-check.

Per cominciare

1. Installatela

Assistente Come
Claude (app per computer e claude.ai) nelle impostazioni, sezione dedicata alle skill, caricate fair-check.skill; serve che sia attiva l’esecuzione di codice. La skill è poi disponibile in tutte le conversazioni e nella scheda Code dell’app
Claude Code dal terminale estraete l’archivio e copiate la cartella fair-check in ~/.claude/skills/
ChatGPT e Codex (OpenAI) estraete l’archivio e copiate la cartella fair-check in ~/.agents/skills/: la leggono l’app ChatGPT per computer, Codex nel terminale e l’estensione per gli editor (documentazione di OpenAI)
Altri assistenti se supportano il formato Agent Skills, copiate fair-check nella cartella delle skill indicata nella loro documentazione; altrimenti, se sanno leggere file ed eseguire Python, date loro la cartella fair-check insieme a quella del progetto e chiedete di seguire SKILL.md

2. Chiedete il controllo

Aprite la cartella del progetto nell’assistente e scrivete, per esempio:

  • Controlla se questa cartella è pronta da depositare su Zenodo.
  • Controlla solo il codice: gira su un altro computer?
  • I numeri del preprint escono dai dati e dagli script?
  • Prepara la versione da depositare.

L’assistente capisce dalla richiesta che serve la skill; potete anche richiamarla per nome (/fair-check in Claude Code, $fair-check in Codex). Nelle versioni web (claude.ai, ChatGPT) allegate la cartella come zip.

Prima di cominciare vi fa alcune domande, tutte insieme (che cosa controllare, dove depositare…). Se rispondete “fai tutto”, usa le risposte predefinite, elencate più sotto. Prima di eseguire comandi chiede il vostro permesso.

3. Leggete il rapporto

Il rapporto è nella vostra lingua ed è ordinato per importanza:

  1. Risultati che potrebbero cambiare, se ce ne sono: un errore nei dati che entra nelle analisi, un punteggio totale calcolato diversamente dai suoi item, un numero del manoscritto che non esce dai dati o dal codice. Per ciascuno: il valore riportato, quello trovato, la tabella o la frase che cambierebbe. Qui potrebbe servire una correzione all’articolo, non solo alla cartella.
  2. Una tabella con lo stato di ogni area: dati, struttura e nomi, formati, README, data dictionary, licenza, codice, pacchetti, manoscritto, dati personali.
  3. I problemi area per area, ciascuno con il file, la colonna o la riga e il dato che lo dimostra (“in 211 righe su 234”, “nel file 96.16, nella Tabella 1 89.77”).
  4. Le cinque o sei cose da sistemare per prime, in ordine.

Quello che non è stato possibile controllare è detto esplicitamente, con il motivo: per esempio “gli script non sono stati eseguiti perché in questo ambiente non c’è R”. Non viene contato come un problema della cartella.

Dati personali

L’assistente legge i file che apre e l’output degli script, e questi passano dai server di chi fornisce il servizio AI. Prima di usare la skill su dati sensibili, controllate consenso informato, regole del vostro ateneo e condizioni del servizio, oppure togliete prima i dati personali. Dettagli.

Nel dettaglio

Che cosa controlla

Uno script legge prima tutti i file e prepara un riassunto per l’assistente: che cosa c’è (dati, codice, manoscritto, file dell’esperimento) e che cosa non va. Ogni segnalazione è marcata come certa (stabilita dallo script) o da verificare: l’assistente controlla queste ultime nei dati, nel README o nel codice prima di riportarle. I controlli dipendono da che cosa c’è nella cartella e da che cosa avete scelto:

Area Che cosa guarda
Dati riconosce che cosa misura ogni colonna (età, genere, tempi di reazione, accuratezza, item di un questionario, condizione) e cerca gli errori tipici di quel dato: un’età di 999, date di nascita al posto dell’età, tempi in secondi mescolati a millisecondi, un 7 fra item da 1 a 5, F e Femmina come due categorie. Ricalcola riga per riga gli item invertiti e i punteggi totali e di sottoscala: un item “invertito” che non lo è, o un totale che somma una colonna in più, cambiano i risultati. Poi: valori mancanti scritti in più modi (NA, -99, cella vuota), righe duplicate, file identici, la stessa persona con valori diversi in due file, ID che non coincidono fra i file
Documentazione nomi di file e colonne, formati, il README e le sue sezioni, un data dictionary per ogni file di dati, licenze diverse per dati e codice
Dati personali nomi, e-mail, indirizzi IP, coordinate, date di nascita, ID di Prolific, risposte a testo libero; quante persone si distinguono dalle altre per la combinazione di età, genere, scuola e simili
Codice esegue gli script in una copia della cartella e dice quali si fermano e perché (setwd(), percorsi assoluti, file mancanti, pacchetti mancanti, un ordine di esecuzione che non funziona); elenca i pacchetti e li confronta con renv.lock; segnala i numeri casuali senza seed
Manoscritto cerca nell’output degli script ogni statistica riportata, frequentista o bayesiana; controlla il testo con sé stesso (reclutati meno esclusi uguale N, gruppi che sommano a N, percentuali, gradi di libertà, scale di risposta e fasce d’età dichiarate); controlla esclusioni, versione del PDF e Data availability

Riconosce i file di Qualtrics, PsychoPy (e Pavlovia), jsPsych (e JATOS), Gorilla, OpenSesame ed E-Prime: sa che cosa scrive ciascun programma, in che unità (key_resp.rt di PsychoPy è in secondi, Reaction Time di Gorilla in millisecondi) e quali colonne contengono dati personali.

Le domande iniziali

Controllare tutto costa tempo e consuma l’uso del vostro abbonamento al servizio AI (stimare di nuovo un modello bayesiano può richiedere un’ora): per questo la skill chiede prima che cosa fare. Le domande sono solo quelle che valgono per la vostra cartella.

Domanda Se non rispondete
Che cosa controllo? Dati e documentazione, il codice, i numeri del manoscritto, la versione da depositare tutto
Avete documenti che aiutano a capire lo studio? Preregistrazione, protocollo, codebook no
Il deposito deve seguire lo standard Psych-DS? no
Dove lo depositerete? Zenodo
Il codice nuovo, se serve, in R o in Python? la lingua dei vostri script
Divido gli script lunghi per fasi (pulizia, analisi, figure)? sì
Uso i modelli già stimati, invece di stimarli di nuovo? sì, se ci sono

La versione da depositare

Viene creata accanto alla vostra cartella, sempre con le stesse sottocartelle:

progetto_deposit/
├── README.md         le otto sezioni della dispensa
├── LICENSE           cosa vale per cosa, poi i testi completi
├── data/             i dati, con nomi come study-stroop_task-flanker_data.csv
│   └── raw/          gli export originali
├── dictionaries/     un data dictionary per ogni file di dati
├── scripts/          il codice, numerato nell'ordine in cui va eseguito
├── output/           figure e tabelle prodotte dagli script
├── materials/        l'esperimento e i materiali propri
└── docs/             preprint, preregistrazione

Prima di costruirla, l’assistente vi mostra il piano e chiede le decisioni che spettano a voi: quali file lasciare fuori, quali colonne personali togliere, se correggere gli errori trovati nei dati, quali licenze usare (predefinite: CC0 per i dati, GPL-3.0 per il codice, CC BY 4.0 per preprint e materiali). Poi aggiorna i percorsi negli script, li esegue di nuovo nella cartella nuova per verificare che funzionino e prepara lo zip da caricare.

Le regole che segue

  • La vostra cartella non viene mai modificata. Tutto quello che la skill scrive va in una cartella temporanea o nella versione da depositare.
  • Cambia il meno possibile. Nei vostri script corregge solo quello che impedisce di eseguirli, nello stile del codice che c’è già, ed elenca ogni modifica. Le correzioni ai dati le propone, non le applica senza il vostro accordo.
  • Non installa pacchetti nel vostro R. Se mancano, ve lo dice e chiede. Nei progetti con renv esegue renv::restore() nella copia: le versioni scritte in renv.lock finiscono nella libreria del progetto copiato.
  • Non inventa. Nel data dictionary scrive solo quello che trova scritto da qualche parte (nei dati, nel README, nel codice, nella documentazione dei programmi); il resto resta TODO, da completare voi.

Che cosa serve sul computer

L’assistente deve poter leggere i file ed eseguire comandi, sul vostro computer o nel suo ambiente. Sul computer che esegue i comandi servono:

Che cosa A che cosa serve Se manca
Python 3 gli script della skill la skill non funziona
R eseguire il codice R il codice viene letto ma non eseguito
openpyxl, pyreadstat (librerie Python) leggere i file Excel e SPSS/Stata quei file non vengono controllati
pdftotext, Ghostscript o pypdf leggere il testo di un manoscritto in PDF l’assistente lo legge da sé, se può

Il rapporto si apre con quello che manca e con le sue conseguenze. Nelle versioni web (claude.ai, ChatGPT) R di solito non c’è.

Che cosa vede l’assistente

Quando l’assistente lavora sul vostro computer (Claude Code, Codex, l’app Claude per computer), la cartella resta lì e gli script girano lì. L’assistente legge però l’output degli script e i file che apre (il README, il codice, qualche riga dei dati), e questi passano dai server di chi fornisce il servizio (Anthropic, OpenAI…) come parte della conversazione. La skill riduce quello che passa: lo script riporta riassunti (tipi, intervalli, conteggi), non le righe dei dati, e non mostra i valori delle colonne che sembrano dati personali. Nelle versioni web, invece, lo zip allegato viene caricato sui server del servizio.

Il formato

La skill segue Agent Skills, un formato aperto: un file SKILL.md con le istruzioni, più gli script e i documenti che servono. Il formato è nato da Anthropic per Claude ed è stato adottato da altri strumenti, tra cui Codex di OpenAI: la stessa cartella funziona con tutti. I sorgenti sono nella cartella skill/ del repository di questo sito.
